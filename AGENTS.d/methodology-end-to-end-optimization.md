# 方法论：端到端优化（功耗 / 性能 / 带宽）

以下原则适用于“设备 + 服务端 + 网络协议”这类端到端系统的优化与排障，目标是用最少改动获得最大的确定性收益，并避免引入不可回滚的隐性语义变化。

## 1. 先量化，再优化（建立基线）

- 先定义成功指标：如唤醒时长、传输字节数、失败率、误唤醒频率、平均功耗。
- 把关键路径拆成阶段（唤醒 → 联网 → 请求 → 处理 → 渲染 → 断网 → 深睡），优先优化占比最高且可观测的阶段。

## 2. 优先消灭“每轮必做”的固定成本

- 任何每次唤醒都要执行的动作，长期都会变成主要耗电项。
- 优先策略是缓存、条件请求、节流、延后执行，而不是微优化 CPU 指令。

## 3. 用标准协议语义换复杂度（协议层优先）

- 能用 HTTP / 缓存语义（`ETag`、`Last-Modified`、`304`、`Cache-Control`）解决的，不自造轮询与一致性协议。
- 优化应落在“减少必要工作量”，而不是“更快地做同样的工作量”。

## 4. 特例路径要显式建模

- 一旦引入缓存或跳过逻辑，必须同步定义“强制刷新 / 人工触发”的语义。
- 让默认路径省电省流，让显式操作确定生效，两者不能互相吞语义。

## 5. 做能力协商，不做硬编码

- 用“声明能力 / 偏好”的方式演进端到端链路，并保持服务端与客户端都支持降级回退。
- 新能力必须可灰度：新端能用，旧端不挂。

## 6. 观测闭环

- 把原因码、来源、路径分支写入日志与上报。
- 优先增加低成本诊断点（字段、计数、时间戳），减少猜测式修复。

## 7. 变更管理以回滚为第一公民

- 按纵向切片或组件边界拆分提交，确保可独立回滚。
- 行为变化必须同步更新 API / 运行手册，避免知识只存在提交历史。

## 8. 无硬件条件下的验证策略

- 用编译、静态检查、最小化集成测试保证不会破坏基本行为。
- 把硬件相关验证点显式列为待验证清单，并提供默认安全的开关 / 回退路径。
