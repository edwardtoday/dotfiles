# 方法论：静态扫描 / CI / 自动化验证（跨项目通用）

## 1. 静态规则修复：语义第一、证据第二、风格第三

- 先定义“行为不变”的可测试标准，再动手改代码。
- 避免机械改写；优先用显式分支、抽函数、清晰命名表达意图。
- 规则冲突时要记录取舍理由：优先更高严重级别与更高质量属性。

## 2. 把 CI 当异步分布式系统看待

- 触发 pipeline 不等于 pipeline 已结束。
- 重试、补跑、延迟执行都可能再次拉取 ref。
- 合并后默认保留源分支，待确认稳定后再清理。

## 3. 自动化默认非交互

- 脚本应在无 TTY / 无 GUI 环境下可运行：`BatchMode=yes`、超时、Fail-fast、明确退出码。
- 远程链路应显式化，不依赖个人 SSH 配置、Agent 或跳板机默认行为。

## 4. 指标闭环：API / 日志是真相来源

- UI 只做展示，决策基于日志与 API。
- 凭证只放受控位置（CI 变量、密钥管理），避免进入仓库与日志。

## 5. 变更管理：小步快跑 + 易回滚

- 单 MR 聚焦一个主题，控制文件数与认知负担。
- 每个主题优先放在独立 `worktree` / `branch` 中推进。
- 合并前先本地复现关键 CI 命令，必要时补最小测试用例锁定行为。
