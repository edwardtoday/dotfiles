# 工作流与模式协议（扩展）

本文档保留详细流程规范；`~/.AGENTS.md` 只保留轻量摘要。

## 1. 适用场景

- 任务较复杂，涉及多阶段推进
- 需要先解释 / 再计划 / 再实现
- 需要长时间连续执行、阶段性心跳或高风险控制

## 2. 建议状态模型

### 监听

- 默认状态
- 只做必要的只读探查以澄清目标
- 不在目标不清时直接进入修改

### Explain

- 用于调查、解释、排障前理解
- 以只读为主，重点建立准确模型
- 输出应包括：调查范围、发现、证据、事实/推断边界、下一步建议

### Plan

- 用于把调查结论转成可执行方案
- 先写分析与推理，再给实施步骤
- 应列出预期修改文件、验证策略、风险点与回滚思路

### Implement

- 基于已确认目标和计划执行变更
- 尽量以小步、可验证增量推进
- 每完成一批相关改动就做对应校验，并汇报结果

## 3. PRAR 详细建议

### Perceive / Understand

- 拆解显性与隐性需求
- 建立系统上下文和影响边界
- 明确完成标准与不可变约束

### Reason / Plan

- 对候选方案做取舍分析
- 先做脑内演练，检查潜在副作用
- 形成最小且清晰的实现路径

### Act / Implement

- 按计划推进，不无端扩展范围
- 优先修复根因，而不是堆表层补丁
- 变更后立即做与范围匹配的校验

### Refine / Verify

- 进行更高层级的整体验证
- 更新相关文档
- 记录遗留风险与后续建议

## 4. 长任务规则

- 心跳与恢复策略详见 `~/.AGENTS.d/long-running-runbook.md`
- 高风险操作、权限边界不明、用户目标变化时立即暂停
- 若用户明确要求连续执行，可持续推进直到完成或遇到阻塞

## 5. 解释类任务的额外要求

- 从用户可见入口追踪到实际执行点
- 必须给出明确证据路径
- 若无充分证据，只能输出推断，不得伪装成事实

## 6. 何时不必完整启用本协议

- 单步、低风险、目标清晰的小任务
- 纯格式化、轻微改文案、简单问答
- 已有明确上下文且无需额外分阶段治理的场景
