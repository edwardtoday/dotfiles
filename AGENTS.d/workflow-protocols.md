# 工作流与模式协议（扩展）

本文档保留详细流程规范；`~/.AGENTS.md` 只保留轻量摘要。

## 1. 适用场景

- 任务较复杂，涉及多阶段推进
- 需要先解释 / 再计划 / 再实现
- 需要长时间连续执行、阶段性心跳或高风险控制

## 2. 建议状态模型

### 准备 / 澄清

- 仅在目标、边界或副作用不清时进入
- 只做必要的只读探查以消除关键歧义
- 目标清晰且风险可控时，不把“监听”当作默认停顿点，直接进入端到端处理

### Explain

- 用于调查、解释、排障前理解
- 以只读为主，重点建立准确模型
- 输出应包括：调查范围、发现、证据、事实/推断边界、下一步动作

### Plan

- 用于把调查结论转成可执行方案
- 用结论、取舍和证据支撑实施步骤，不展开私有思维链
- 应列出预期修改文件、验证策略、风险点与回滚思路

### Implement

- 基于已确认目标和计划执行变更
- 尽量以小步、可验证增量推进
- 每完成一批相关改动就做对应校验，并汇报结果

## 3. 检索预算

动态信息、联网资料、仓库考古和日志检索都应有停止条件，避免为改善措辞而无限查资料。

- 普通问答：先做一次短关键词、高辨识度检索；若结果足以支撑核心结论，回答并停止。
- 官方或易变信息：优先官方、一手来源或本地真实配置；除非缺关键字段，不继续找二手材料。
- 指定材料：用户给定 URL、文件、issue、MR、日志或数据集时，必须读取指定对象本身。
- 继续检索仅在以下情况发生：核心问题未被回答；缺必要的日期、版本、ID、owner、配置、命令或证据；用户要求全面覆盖或对比；答案会包含重要但尚无支撑的事实主张。
- 不为润色、补例子、支持非关键背景或扩大叙事继续检索；可以把不确定事实泛化或标注为推断。

## 4. 验证矩阵

验证要与任务风险和变更面匹配；无法运行验证时，说明原因和下一最佳检查。

| 任务类型 | 优先验证 |
| --- | --- |
| 代码行为变更 | 目标单测、相关集成测试、类型检查、lint、构建，按影响面从小到大选择 |
| 配置 / dotfiles / 脚本 | 语法检查、source/加载测试、dry-run、关键命令 smoke test |
| 运维 / 部署 | 变更前状态、执行日志、变更后状态、健康检查、回滚路径 |
| 文档 / runbook | 路径存在、命令可执行性、链接或引用有效性、与当前实现一致 |
| 数据 / 批处理 | 抽样校验、计数校验、幂等性检查、错误日志复核 |
| 前端 / 视觉产物 | 实际渲染、截图检查、响应式视口、布局截断和控制台错误 |

## 5. 长任务规则

- 心跳与恢复策略详见 `~/.AGENTS.d/long-running-runbook.md`
- 高风险操作、权限边界不明、用户目标变化时立即暂停
- 若用户明确要求连续执行，可持续推进直到完成或遇到阻塞

## 6. 解释类任务的额外要求

- 从用户可见入口追踪到实际执行点
- 必须给出明确证据路径
- 若无充分证据，只能输出推断，不得伪装成事实

## 7. 何时不必完整启用本协议

- 单步、低风险、目标清晰的小任务
- 纯格式化、轻微改文案、简单问答
- 已有明确上下文且无需额外分阶段治理的场景
