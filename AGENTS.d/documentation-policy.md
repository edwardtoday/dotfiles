# 文档协议（扩展）

本文档定义何时需要文档、需要到什么程度、何时必须同步更新。核心原则：文档服务真实维护，不为模板制造负担。

## 1. 总体规则

- 只在相关行为、接口、配置、安装、部署、使用方式或已知限制变化时同步文档。
- 优先沿用项目已有文档结构；小型脚本、个人工具和 dotfiles 不强制建立完整 `/docs` 体系。
- 新增文档前先判断是否有明确读者和后续维护价值。

## 2. 文档层级

- 小型项目：通常保留一个可用 `README.md`，必要时补关键配置、运行示例或故障排查。
- 中型项目：在 `README.md` 外，按需补运行 / 部署说明、模块说明或设计记录。
- 大型或高风险项目：确有协作、审计或长期运营需求时，再引入架构设计、运行手册、迁移说明、RFC / PRD 等专题文档。

## 3. 更新优先级

1. 优先更新真正会被读到的 `README.md` 或现有操作说明。
2. 其次更新与变更直接相关的架构、部署、接口或 runbook 文档。
3. 仅在有持续维护价值时更新 backlog、路线图或专题文档。

## 4. 反模式

- 为小仓库强行创建整套 PRD / SRS / 技术设计文档。
- 每次微小内部重构都同步更新所有文档。
- 复制模板后长期留空，制造虚假完备感。
