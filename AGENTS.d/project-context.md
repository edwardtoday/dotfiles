# 项目上下文协议（扩展）

本文档定义**何时需要项目级上下文文件，以及项目级文件应记录什么**。

## 1. 何时建议建立项目级上下文文件

出现以下任一情况时，建议在仓库根目录维护项目级 `AGENTS.md` / `CLAUDE.md` / `GEMINI.md`（按所用工具选择其一或用软链统一）：

- 项目有明显区别于全局规则的约束
- 项目结构复杂，首次进入成本较高
- 有多人协作、交接或长期维护需求
- 有项目特有的运行、测试、发布或安全要求
- 存在必须反复提醒的本地约定或禁区

如果项目较小、结构简单、没有明显特例，可不额外创建项目级上下文文件。

## 2. 项目级上下文文件建议包含的内容

可按需选择，不要求机械补齐：

- 项目目标的高层描述
- 架构概览或关键模块划分
- 关键技术与框架列表
- 主要目录、入口文件或关键路径说明
- 本地开发、测试与运行方式
- 项目特有约定，或对全局规则的补充 / 偏差

## 3. 编写原则

- 只写“这个项目独有、对后续工作有帮助”的信息。
- 优先帮助第一次接手的人快速建立正确心智模型。
- 如果某条信息已经稳定地写在 `README.md` 或其他项目文档中，不必重复复制。
- 项目级上下文文件应短小、稳定、可维护，避免膨胀成第二份总文档。
