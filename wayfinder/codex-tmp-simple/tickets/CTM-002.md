## Question

基于当前 `~/.codex/tmp` inventory、最大目录样本、历史迁移台账和恢复事故，将内容按规范工作区副本、可再生产物、任务检查点、证据归档、共享缓存、活跃进程依赖和未知遗留物分层；每层的真实恢复价值、可验证替代来源、占用规模和误删后果是什么？

## Resolution

研究结论见 [当前 tmp 内容价值分层](../research/tmp-content-value.md)。当前约 61.1 GiB 的主要问题不是检查点本身，而是 clean clone/worktree、构建输出、重复研究副本和无 owner 的自动收养目录长期驻留；18 个无 owner、无 required path 的 active 目录约占 25.06 GiB，常见可再生产物至少约 6.37 GiB。

真正需要 tmp 保护的内容只有：尚未锚定的 Git 状态、尚未交付的小型非 Git 检查点或原始证据，以及进程仍持有期间的工作集。规范仓库副本、依赖、构建输出、SDK/工具链、已归档 evidence 和可从外部恢复的任务主体均不应由 tmp 长期保存。现有 6.486 GiB 主体收缩为 8 KiB stub 的案例证明“权威外部锚点 + 小检查点”可行，但显式 compact 的采用率不足，不能作为最终日常流程。

报告只支持分层和迁移优先级，不授权按目录名直接删除；每个 legacy 目录仍需验证 Git、进程引用和替代来源。
