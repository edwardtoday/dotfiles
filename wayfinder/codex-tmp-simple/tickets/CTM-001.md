## Question

基于当前 Codex 官方手册和本机可验证行为，chat history、resume、managed worktree、snapshot restore、worktree retention、handoff、Goal mode 和 automation 分别保存什么、何时失效、哪些能力可替代自建 tmp 持久化；最终应把哪些内容明确排除出自建临时工作区的职责？

## Resolution

研究结论见 [Codex 官方恢复能力合同](../research/official-recovery-contract.md)。自建 tmp 只负责例外性的唯一非 Git 检查点；已持久化且非 ephemeral 的 transcript、Goal 已保存的目标与生命周期、明确迁入 Scheduled 的触发计划，以及 managed worktree/handoff 已覆盖的 Git 状态，不应再复制进 tmp。

这些产品能力不是通用备份：managed-worktree snapshot 的文件覆盖、保留期和校验合同未公开；handoff 默认不移动 ignored 文件；聊天附件随本地 session 存续；外部调度 ledger、ack、执行游标和独立验收证据仍需各自权威载体。删除 tmp 内容前必须验证替代来源实际存在，不能仅凭“Codex 应该能恢复”。

证据边界以报告中的官方文档版本、源码提交和本机观察为准；本票不授权删除。
