### 数据库与存储：AWS 选型指南（含中国区与全球区差异）

AWS 提供丰富的数据库与存储服务，需根据业务需求、数据模型和合规要求合理选择。中国区（由光环新网/西云数据运营）与全球区服务名称一致，但部分功能上线略有延迟，需查阅[中国区服务列表](https://www.amazonaws.cn/en/about-aws/regional-product-services/)。

| 数据库/存储         | 数据模型             | 典型场景                                                                                           | 适用时机                                                                                                     |
| ------------------ | -------------------- | -------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| **Amazon RDS**     | 关系型（MySQL/Postgres/SQL Server等） | **默认首选。** 电商订单、金融数据、用户凭证、结构化数据                                             | 需要 ACID、复杂查询、关联、传统关系型数据库可靠性时                                                          |
| **Amazon Aurora**  | 关系型（兼容MySQL/Postgres，分布式高可用） | 高并发、自动扩展、企业级高可用数据库                                                                | 需要比RDS更高的性能与可用性，或多区域容灾时                                                                  |
| **Amazon DynamoDB**| NoSQL（键值/文档型） | 用户资料、实时聊天、活动流、IoT、半结构化数据                                                      | 需要毫秒级响应、自动扩缩、无服务器管理、超大规模NoSQL场景                                                    |
| **Amazon Redshift**| 分析型数据仓库       | BI 报表、日志分析、ML 数据输入                                                                      | 需对超大数据集做复杂分析查询时（**非事务型数据库**）                                                         |
| **Amazon S3**      | 对象存储             | 用户上传图片/视频、静态资源、备份、数据湖                                                          | 存储非结构化文件，应用只需在数据库中存储对象 URL                                                             |
| **Amazon ElastiCache** | 内存缓存（Redis/Memcached） | 热点数据缓存、会话管理、排行榜、低延迟访问                                                          | 需要极低延迟、减轻数据库压力时                                                                               |

**中国区与全球区注意事项：**
* RDS、Aurora、DynamoDB、S3、Redshift、ElastiCache等主流服务均已在中国区上线，但部分高级特性（如Aurora Serverless、部分Redshift功能）可能延后开放。
* 服务API、SDK调用方式与全球区一致，部署与合规需遵循中国区本地法规。
* 跨区（中国区与全球区）数据完全隔离，需分别部署与管理。

> 推荐：如无特殊需求，结构化数据优先选用 Amazon RDS（Postgres/MySQL），高并发/弹性NoSQL场景选用 DynamoDB，文件/静态资源统一用 S3 存储。大数据分析用 Redshift，缓存用 ElastiCache。
