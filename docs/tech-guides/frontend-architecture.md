### 前端架构：UI 框架选型指南

本指南提供前端技术选型决策框架，重点考虑目标平台（Web/Mobile）与复杂度。

#### **1. Web 优先应用**

**目标：** 构建以 Web 浏览器为主要体验载体的功能丰富应用。

* **首选：Next.js（React）**
  * **适用场景：** 面向公众、内容丰富、需 SEO/性能/全栈能力的复杂 Web 应用。Next.js 提供一体化全栈体验，是现代 Web 开发的标准。
* **备选：Vite + React**
  * **适用场景：** 内部工具、管理后台、复杂 SPA，对 SEO 无要求，追求开发效率。其热重载体验极佳。
* **企业级备选：Angular**
  * **适用场景：** 大型、复杂、团队协作需求高的企业级应用。Angular 的全家桶和强约束结构非常适合此类场景。

#### **2. 移动优先应用**

**目标：** 用一套代码同时为 iOS 和 Android 构建高性能原生应用。

* **首选：Flutter**
  * **适用场景：** 当核心产品是移动 App 时。Flutter 单一代码库、原生性能和极佳开发体验，是构建高质量跨平台移动应用的首选。
  * **注意：** 虽然 Flutter 可编译为 Web 应用，但不适合内容型或 SEO 驱动的网站。仅当 Web 是次要目标时选择 Flutter。

#### **决策参考表**

| **如果你的主要目标是...**                                   | **推荐选择是...**         |
| -------------------------------------------------------- | ------------------------ |
| 面向公众、内容丰富或全栈 Web 应用                         | **Next.js**              |
| 高度交互的内部工具或管理后台                              | **Vite + React**         |
| 大型、复杂、开发者众多的企业级应用                        | **Angular**              |
| 高性能、跨平台的移动应用（iOS & Android）                 | **Flutter**              |
