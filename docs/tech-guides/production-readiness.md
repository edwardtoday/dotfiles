### 企业级生产就绪性（AWS 专用：中国区与全球区）

本节聚焦于 AWS 平台（含中国区与全球区）下，确保应用真正生产可用、安全、可维护的三大支柱：安全、测试、可观测性。中国区与全球区服务名称一致，但部分功能上线略有延迟，需查阅[中国区服务列表](https://www.amazonaws.cn/en/about-aws/regional-product-services/)。

#### 1. 用户认证与授权

此为关键安全功能，**绝不可自研**。

* **原则：** 始终使用托管身份服务，避免自建认证系统。
* **推荐：**
  * **Amazon Cognito**（全球区与中国区均可用）：AWS 原生托管身份服务，支持用户注册、登录、社交登录、MFA、OAuth/OpenID Connect，易于与 AWS 生态集成。适合绝大多数 Web、移动和 API 场景。
  * **第三方方案（如 Authing、Auth0、Okta）：** 如需更丰富的企业级特性、跨云或合规需求，可选用。中国区推荐 Authing（本地化支持好），全球区可选 Auth0/Okta。
* **注意事项：**
  * Cognito 在中国区与全球区 API 基本一致，但部分高级特性（如某些社交登录、托管 UI）可能上线延迟。
  * 所有敏感数据和凭证需遵循中国区本地合规要求。

#### 2. 深度可观测性：不仅仅是日志

理解和调试分布式系统，日志远远不够。

* **结构化日志：** 所有服务**必须**输出 JSON 格式日志，便于在 **Amazon CloudWatch Logs** 检索和分析。中国区与全球区均支持 CloudWatch。
* **分布式追踪：** 推荐集成 **AWS X-Ray**，实现端到端请求追踪，定位前后端及各服务间的瓶颈和错误。X-Ray 在中国区与全球区均已上线。
* **指标与告警：** 在 **CloudWatch Metrics** 定义并监控关键指标（KPI）和服务目标（SLO），如 p99 延迟>2s、错误率>1% 时自动告警。可用 **CloudWatch Alarms** 配置自动通知。

#### 3. 主动安全防护

安全是持续过程，而非一次性配置。

* **自动化漏洞扫描（CI/CD）：**
  * **依赖扫描：** CI 流水线**必须**包含 `npm audit`、`pip-audit` 或等效工具，检测三方包漏洞。
  * **容器扫描：** 推荐使用 **Amazon ECR 镜像扫描**（全球区与中国区均支持基础扫描），自动分析 Docker 镜像的已知系统级漏洞。也可集成 Trivy、Clair 等开源工具。
* **额外建议：**
  * 启用 **AWS Security Hub**（如可用），统一聚合安全告警与合规检查。
  * 定期使用 **IAM Access Analyzer** 检查权限过宽风险。
  * 严格区分中国区与全球区的安全策略和合规要求，分别配置和管理。
