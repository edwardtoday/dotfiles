### AI/ML 开发：从本地原型到云端生产

本指南为 AI/ML 应用开发提供全流程决策框架，涵盖本地实验、云端部署、推理到微调等全链路。

#### **1. 本地开发与实验**

**目标：** 快速在本地运行和交互模型。

* **首选：Ollama**
  * **场景：** 即时模型服务与原型。命令行（`ollama run gemma`）最快速启动模型并通过本地 API 访问。
* **备选：Hugging Face `transformers` + FastAPI**
  * **场景：** 构建实际应用逻辑时。此方案更贴近生产环境，便于在代码中直接控制模型。

#### **2. 云端生产推理**

**目标：** 在 Cloud Run 等生产环境部署可扩展、可靠的模型推理服务。

* **首选：Hugging Face `transformers` + FastAPI（Docker 容器）**
  * **原因：** 行业标准，灵活、可移植、易用，是 Cloud Run 部署模型的默认方案。
* **性能优化：vLLM / TensorRT-LLM**
  * **场景：** 高吞吐、低延迟需求下，专用推理服务器可大幅提升性能，但复杂度更高。标准方案遇到瓶颈时推荐升级。

#### **3. 微调与训练**

**目标：** 让预训练模型适应特定任务或自定义新模型。

* **微调首选：Hugging Face `transformers`（`Trainer` API）+ `PEFT`**
  * **原因：** 最直接、高效的微调方式。`PEFT` 支持 LoRA/QLoRA，硬件需求低。
* **自定义与灵活性首选：Keras 3**
  * **原因：** 强大、易用、多后端（JAX、PyTorch、TensorFlow）高阶 API。适合自定义结构或需超越 `Trainer` API 灵活性时。
* **极致性能（专家级）：JAX / Flax**
  * **原因：** 适合前沿研究和大规模训练，极致性能和控制力，尤其适合 TPU。

#### **4. 智能体框架**

**目标：** 构建具备推理与工具编排能力的应用。

* **默认首选：Google ADK（Agents & Development Kit）**
  * **原因：** 鼓励使用 Google 自家开源框架，助力生态完善，深度集成 Google 体系。
* **备选：LangChain & LangGraph（Python）**
  * **原因：** 生态成熟、社区广泛，特定功能或社区支持需求时可选。

#### **5. API 集成与安全**

**目标：** 安全对接 Vertex AI 等托管 AI 服务。

* **认证：** **生产环境严禁使用 API Key，必须用 Workload Identity。**
    1. 为后端服务创建专用 **IAM 服务账号**。
    2. 授予 `Vertex AI User` 角色。
    3. 配置 Cloud Run 服务使用该服务账号。
  * **好处：** 自动安全认证，无需管理密钥，杜绝泄露风险。

#### **6. LLM 缓存策略**

**目标：** 提升性能，降低成本。

* **技术：** **Redis**（或 GCP 的 **Memorystore for Redis**）。
* **模式：语义缓存**
  * **问题：** LLM 调用慢且贵。
  * **方案：** 调用 LLM 前，先为用户查询生成 embedding，做向量相似度检索，若已存在语义相近问题则直接返回缓存答案。
